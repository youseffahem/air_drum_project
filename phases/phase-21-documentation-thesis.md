## Purpose

Produce the thesis material and project documentation from the evaluated RC and the archived results: chapter map aligned to phases, figures and tables regenerated from manifests, a **claims audit** in which every quantitative or qualitative claim is tagged MEASURED / VALIDATED / PENDING / Target / Historical and linked to its source, the dataset card and labelling rules as appendices, the limitations chapter, the reproducibility appendix, and developer/user documentation.

## Why This Phase Exists

The grading and scientific defensibility of the project (success criterion 3) depend on the thesis accurately reflecting what was built and measured. The claims audit operationalises the research-integrity rules (README §13) one last time, on the final text.

## Relationship to Research Contribution

Communicates the contribution with its evidence and its limits; prevents overclaiming (e.g. effective-latency reduction without external measurement).

## Detailed Tasks

### Task 21.1 — Chapter Map and Outline
- **What:** Map chapters/sections to phases and artefacts; define which figures/tables each section needs.
- **Why:** Structure; completeness.
- **Depends on:** Reports.
- **Evidence:** Outline document.

### Task 21.2 — Figure/Table Regeneration Pipeline
- **What:** Scripts that read stored results (Phases 09/10/11/18/19) and produce every figure/table with a caption containing the manifest hash and label (MEASURED etc.); primary figure = lead time vs. FP per arm (Phase 18).
- **Why:** No hand-typed numbers; reproducibility.
- **Depends on:** Manifests.
- **Evidence:** Regeneration run; figure list.

### Task 21.3 — Claims Audit
- **What:** Extract every claim from the drafts; tag with status and source; flag any claim that (a) presents a target as measured, (b) states latency reduction without Phase 18 external measurement, (c) describes planned work as implemented, (d) uses "60 FPS" without native evidence, (e) omits the geometric-ground-truth caveat, (f) implies the marker condition is primary; fix or reword; keep the audit table as an appendix.
- **Why:** README §13; Q60.
- **Depends on:** Drafts.
- **Evidence:** Audit table with zero unresolved flags.

### Task 21.4 — Limitations Chapter
- **What:** Consolidate Phase 07 (geometric GT, acoustic offset), Phase 17 (failure catalogue), Phase 18 (threats to validity), Phase 19 (dependencies); include measurement uncertainties; include what could not be measured (PENDING items).
- **Why:** Success criterion 3.
- **Depends on:** Reports.
- **Evidence:** Chapter draft.

### Task 21.5 — Reproducibility Appendix
- **What:** Environment, dataset/labels versions, split files, model hashes, harness version, commands to re-run every experiment from raw data; expected outputs and tolerances; hardware descriptor.
- **Why:** README §4 VALIDATED.
- **Depends on:** Phase 18/19 packages.
- **Evidence:** A second person follows the appendix to regenerate one headline table (recorded).

### Task 21.6 — Developer and User Documentation
- **What:** Architecture/contracts (from Phase 01, updated), module guide, phase scripts index, config reference, calibration/user guide, troubleshooting (from Phase 17 messages).
- **Why:** Q56/Q57 usability; handover.
- **Depends on:** RC.
- **Evidence:** Docs reviewed by someone other than the author (recorded).

### Task 21.7 — Requirements Coverage Table
- **What:** From the RTM: each REQ → evidence artefact → status (VALIDATED / MEASURED / IMPLEMENTED / PENDING / out of scope).
- **Why:** Shows what was and was not delivered.
- **Depends on:** RTM; gates.
- **Evidence:** Table in the thesis appendix.

### Task 21.8 — Supervisor Review Cycle
- **What:** Draft → review → revisions; record review comments and resolutions.
- **Why:** Quality.
- **Depends on:** All above.
- **Evidence:** Review log.
