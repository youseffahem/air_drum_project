## Context

Task 03.1 wraps "the candidate landmark estimator (MediaPipe Hands)" so that it outputs `HandObservation` in ROI-normalized y-down coordinates, exposes its parameters via config, and records a `detector_id` with version. Four facts found while implementing it require decisions that later tasks and phases must be able to rely on:

1. **API generation.** The pinned `mediapipe==1.0.1` (docs/environment.md) ships the **Tasks** API (`mediapipe.tasks.python.vision.HandLandmarker`), not the legacy *Solutions* `mp.solutions.hands`. The Tasks API has **no `model_complexity` parameter**; the model is a downloaded `.task` file. Its parameters are `num_hands`, `min_hand_detection_confidence`, `min_hand_presence_confidence`, `min_tracking_confidence` and a running mode (`IMAGE` per-frame, `VIDEO` with the estimator's own inter-frame hand-ROI tracking, `LIVE_STREAM` asynchronous callback).
2. **Model file.** The `.task` file is not bundled with the wheel; it must be downloaded once. `docs/environment.md` §7 already fixes the rule: downloaded by a documented script, stored under `assets/`, SHA-256 in a manifest, loaded from disk (REQ-052/REQ-209: no network at runtime).
3. **Visibility.** On the pinned model every `NormalizedLandmark.visibility` and `.presence` is `None` (probed on dev captures, run `20260921-1003-p03-hands-check-video`: `visibility_frames = 0` over 514 frames). The phase document's Open Question ("Are landmark visibility scores available from the chosen estimator?") is answered **no** for this estimator; `HandObservation.landmark_visibility` is `null` and stick-tip confidence (Task 03.7) must be derived otherwise.
4. **Handedness label vs anatomy.** The estimator returns a `Left`/`Right` category per hand. On HW-01's raw DSHOW frames the hand on the *image-left* side is labelled `Right` (mean wrist `x ≈ 0.38` for `RIGHT`, `≈ 0.66` for `LEFT` in the well-exposed capture). Whether that label matches the person's anatomical hand depends on whether the camera path mirrors the image, which **cannot be settled from pixels alone** — it needs a person at the camera raising a known hand. Stable identity over time is Task 03.2, not this task.

## Decision

1. **Estimator candidate:** MediaPipe Tasks Hand Landmarker (`mediapipe==1.0.1`, CPU delegate), wrapped by `spacedrums.hands.HandLandmarker` behind a small `LandmarkBackend` Protocol so tests inject a deterministic backend and the estimator family can be swapped (`hands.detector` is an enum of one value; a second family is an enum extension + ADR). The wrapper is the **only** place library coordinates exist (`spacedrums.hands.coords`, ADR-0005/architecture.md §9); conversion runs native → full-frame px → ROI-normalized through `spacedrums.capture.roi.px_to_norm`, the single px↔normalized implementation.
2. **Model asset policy (repo layout amendment):** `assets/models/hand_landmarker.task` is fetched once by `scripts/fetch_hand_landmarker_model.py` from the **versioned** Google bucket path (`…/float16/1/…`, never `latest`) and pinned in `assets/models/manifest.json` (`asset_id`, file, URL, SHA-256, bytes, licence Apache-2.0, `mediapipe` version). `spacedrums.hands.model_asset.resolve_model_asset` re-hashes the file at load and refuses a mismatch. `HandObservation.detector_id` embeds the hash prefix, so any run log names the exact model. **Owner decision (Phase 03 gate C-03-5, 2026-09-21): MANIFEST-ONLY** — `assets/models/*.task` is git-ignored, the manifest is tracked, and `scripts/fetch_hand_landmarker_model.py` re-creates and verifies the pinned file on any checkout.
3. **Config schema 1.1 → 1.2** (minor, additive): optional top-level `hands` block — `detector`, `model_asset_id`, `running_mode ∈ {VIDEO, IMAGE}`, `num_hands`, the three confidence thresholds, `input ∈ {ROI, FULL}`, `swap_handedness`. 1.0/1.1 documents stay valid; a loader cross-field check refuses a `hands` block in a document declaring `< 1.2`. `LIVE_STREAM` is deliberately not offered: its asynchronous callback would create a second place where timing is stamped (ADR-0004 rule: capture stamps, the loop processes in `frame_id` order). "Model complexity" in the task wording maps to `model_asset_id` (the model file) — there is no other knob. A **fragment declares the schema version of the merged document it forms**: the HW-01 camera fragment therefore says `1.2` while its own blocks are unchanged.
4. **`detector_id` format:** `<family>@<lib version>:<sha256 prefix 12>:<mode>:nh<N>:d<det>:p<pres>:t<track>:<input>:swap<0|1>` (e.g. `mediapipe-hand-landmarker@1.0.1:fbc2a30080c3:video:nh2:d0.50:p0.50:t0.50:roi:swap0`). Every parameter that changes the output is in the id.
5. **Emission rule for Task 03.1 (raw labels):** two `HandObservation`s per frame in the fixed order LEFT, RIGHT (architecture.md §3). `hand_id` = the estimator's label mapped by `swap_handedness`. Two detections with the same label → the higher `handedness_score` is emitted, the other is **dropped and counted** (`label_collisions`), never re-labelled by a guess; unknown labels are counted (`unknown_labels`) and not emitted. `num_hands` caps detections at the estimator; nothing beyond LEFT/RIGHT is ever emitted (contracts.md §3.2 "extra detected hands are not emitted"). Task 03.2 replaces the raw mapping by temporal identity assignment and inherits these counters.
6. **Timestamps:** `VIDEO` mode requires strictly increasing integer milliseconds; they are derived from `t_capture` relative to the first frame (never from `time.*`), bumped by 1 ms and counted (`timestamp_bumps`) if two frames share a millisecond. Per-frame processing time is `timing.now()` around the backend call and is a duration, never stored in a record.
7. **Visibility:** `landmark_visibility = null` for this estimator (finding 3). If a future model provides scores, the wrapper passes them through unchanged; nothing derives a fake visibility.
8. **Handedness anatomical check:** `swap_handedness` defaults to `false` (raw label). **Closed 2026-09-21** by the owner (evidence note P-03.1-1): the owner's raised anatomical right hand appears on the image-left side of the live window, where the estimator emits `Right` → the image is not mirrored and `swap_handedness = false` is the decided value for HW-01. A different camera path (external camera, Q22) repeats the one-minute check.
10. **Identity assignment (Task 03.2 amendment, 2026-09-21):** `spacedrums.hands.identity.IdentityAssigner` combines the swap-mapped estimator label (`p_label = score` if the label is the hand, else `1 − score`) with continuity to the hand's previous wrist (`p_temp = max(0, 1 − d / gate_distance)`, undefined after `max_gap_s`) into `s = w_label·p_label + (1 − w_label)·p_temp`, and picks the injective hands→detections map with the highest total by enumeration. `handedness_score` in `HandObservation` **is this combined identity confidence** (producer-defined semantics, contracts.md §1 "Labels"). If the best total beats the runner-up by less than `ambiguity_margin` the frame is **AMBIGUOUS**: both hands are still emitted (their positions are real) but every `handedness_score` is capped at `ambiguous_score_cap`, and the loader enforces `tracking.c_min ≤ cap < tracking.c_valid`, so an ambiguous identity can be `DEGRADED` at most, never `VALID` (README §8, Q33) — the "mark both hands DEGRADED rather than guessing" rule made structural. Contract for Task 03.7/03.13: `tip_confidence ≤ handedness_score` of the same hand, so the cap propagates to `TrackState.status`. Events `LABEL_OVERRIDE` (continuity beat the label = a raw label swap), `CONTINUITY_OVERRIDE` (label beat the nearest previous wrist — expected at a genuine crossing), `IDENTITY_JUMP` (possible track swap) and `AMBIGUOUS` are logged (`logging`, INFO) and written by the check script. Mode `RAW` keeps the Task 03.1 label-only rule as the measurement baseline. Config: `hands.identity` sub-block (required within `hands`; still schema 1.2 — the block was added the same day, before any 1.2 document existed outside this repository); the `detector_id` gains an `id-raw` / `id-temporal-…` fragment carrying every identity parameter. No velocity prediction: the phase document names the *nearest previous wrist position*; a predicted position is a later tunable if Task 03.11 evidence asks for it.
12. **Grip reference points (Task 03.3 amendment, 2026-09-21):** grip point = weighted mean of index MCP (0.4), thumb IP (0.2), thumb tip (0.2), middle MCP (0.2) (tunable, `hands.grip.point_weights`); hand span = max(wrist→middle MCP, pinky MCP→index MCP) (either baseline alone foreshortens in a camera-facing fist). **Direction prior default `KNUCKLE_ROW`** (pinky MCP → index MCP, pointing to the thumb/index side where the tip exits): the phase document's candidates `WRIST_TO_GRIP` and `INDEX_MCP_TO_PIP` both run along the fingers, which in a closed grip is *perpendicular* to the stick — on the dev-capture overlays the search region built from them missed the stick entirely, while the knuckle-row prior put the region on the stick and let the axis fit succeed on 91 % of hand-frames (development sweep, exp-5). Both original candidates remain selectable. The image-plane angle is aspect-corrected; the unit direction stays in the ROI-normalized frame (contract).
11. **Layout amendments** (`docs/repo-layout.md`): `assets/models/` (+ manifest) created by Phase 03; `scripts/_devcapture.py` (dev-capture replay reader, a script helper like `_runlog.py`, to be promoted into `capture.ReplayFrameSource` by Phase 09/13 rather than re-implemented); `scripts/hands_landmark_check.py`, `scripts/fetch_hand_landmarker_model.py`; `tests/hands/`; `docs/reports/` for task evidence notes.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Legacy `mp.solutions.hands` (has `model_complexity`) | Not shipped in `mediapipe 1.0.x`; would force a downgrade with older wheels on Python 3.11 (environment.md risk). |
| Bundle the model in the wheel / vendor it under `src/` | Two copies of a binary; `assets/` with a manifest is the rule already written in environment.md §7. |
| `latest` model URL | Un-pinnable: the file behind it can change silently; a run log could not name the model. |
| `LIVE_STREAM` running mode | Asynchronous result callback: a second stamping site and a result that may arrive for a stale frame — the T2 pattern of ADR-0009, which is a Phase 16 decision, not a Task 03.1 default. |
| Resolve label collisions by position (left-most = RIGHT) in Task 03.1 | That *is* identity assignment (Task 03.2) and would hide swaps inside the wrapper; counting and dropping keeps the raw estimator behaviour measurable. |
| Hungarian assignment (Task 03.2) | Two hands × ≤ 4 detections: enumeration is exact, trivially cheap and lets the runner-up total define the ambiguity margin directly. |
| Fixed image-side prior (image-left = RIGHT) as a third term | Would hard-code the non-crossing case and silently fight every genuine crossing; continuity + label already resolve the same-label case, and a prior is a Phase 05/17 experiment if swaps prove frequent. |
| Re-label ambiguous frames by the higher score | A guess; README §8 / Q33 require DEGRADED instead. The cap + loader rule makes the guess impossible downstream. |
| Constant-velocity predicted wrist for continuity | The phase document specifies the *nearest previous wrist*; prediction adds a tunable that Task 03.11's evidence may or may not justify. |
| Hard-code the handedness swap from the MediaPipe documentation's "mirrored input" note | The observed label on this camera path contradicts a naïve reading, and the anatomical truth needs a person; a config switch keeps the decision explicit and reversible. |
| Make `hands` a required block (bump to 2.0) | Breaks every 1.0/1.1 document for an additive field; contracts.md §8 reserves major bumps for breaking changes. |

## Consequences

- `HandObservation` producer exists (contracts.md §3.2 status: IMPLEMENTED for the class and the wrapper; the record schema is unchanged).
- Every later Phase 03 stage receives ROI-normalized landmarks, `present` flags and a `detector_id`; `landmark_visibility` is `null` — Task 03.7 confidence design must not rely on it.
- The estimator costs **33–47 ms median per 560×440 frame on HW-01** (MEASURED, runs `20260921-1003-…-video` / `20260921-1004-…-image`) — comparable to the 33 ms frame period at a requested 30 FPS (arithmetic). Phase 16's budget starts from this number; Task 03.14 re-measures with the full stage chain.
- Landmark presence collapses with under-exposure at L2 on HW-01 (exposure −5: both hands in 99/171 frames; −6: 10/171; −7: 0/172 — MEASURED, same runs). This is direct evidence for Phase 02 gate items **F-3** (fragment exposure −6 vs owner's −5) and **C-5** (exposure per lighting condition before the freeze), and for Task 03.11's lighting rows: the exposure that maximises sensor rate is not the one that keeps hands detectable.
- Raw label collisions are frequent when detection is marginal (22/171 frames at −6 in VIDEO mode; 4/171 at −5). Task 03.2's assigner resolves them by continuity (exp-6: both hands present in 32 vs 10 frames; 28 label overrides, 4 ambiguous frames, 0 identity jumps — MEASURED, run `20260921-1046-p03-hands-check-video-idtemporal`; details in `docs/reports/phase-03-task-03.2-identity.md`). The estimator itself labelled both hands `Right` with ≥ 0.96 confidence on consecutive frames (exp-6 frames 21–23): `handedness_score` from the estimator alone is not a usable identity confidence in dim light.
- Deliberate-crossing swap rate is **PENDING**: no dev capture with crossings exists and Task 03.2 was executed without new recordings (owner rule); synthetic crossings are covered by `TEST-HANDS-4`.
- `configs/README.md`, `configs/schema/README.md`, `docs/repo-layout.md`, `docs/environment.md`, `scripts/README.md`, `tests/README.md` updated; RTM rows (REQ-103 …) advance only at the Phase 03 gate on the owner's signature (gate-procedure §4).
