## Context

Phase 05 assembles the first end-to-end playable pipeline with two non-learned strike sources — Baseline A (reactive, observed crossing) and Baseline B (rule-based kinematic extrapolation) — behind the Phase 01 `Anticipator` / `Geometry` / `CommitPolicy` contracts, plus the commit logic that every later arm (C-*) must reuse unchanged. Several details were left open by the architecture and had to be fixed to implement it:

1. where the Phase 04 valid-entry threshold `v_min` lives in the configuration (it was only a `GeometryEngine` constructor argument);
2. how "one commit per episode" applies to an **anticipatory** commit, whose crossing has not been observed yet;
3. how shadow logging is realised so that a shadow arm's decisions do not depend on the active arm;
4. what `t_now` is in a replay / synthetic run so that a replay reproduces the committed-strike list (the `Δ_proc` policy is Phase 09's, but Phase 05 needs a provisional value);
5. how `AudioEvent.t_audio_out_est` / `TimingRecord.t_audio_out_est` behave while the audio profile has **no accepted output-latency measurement** (Phase 04 criterion 6 is PENDING on HW-01).

## Decision

1. **Config schema 1.3 — optional `geometry` block.** `geometry.v_min` (minimum inward crossing speed of the Phase 04 valid-entry test, ROI-norm/s) becomes a configuration value shared by every candidate source. Additive minor bump: 1.0–1.2 documents stay valid and have no block; the loader rejects a `geometry` block in a document that declares < 1.3; the live app refuses to start without the block (it never guesses `v_min`). `anticipator.rule.params` stays a free object validated by `spacedrums.prediction.RuleSettings` (unknown keys rejected) — no schema change for rule thresholds. `arms` remains optional in the schema (Phase 01 documents) and is required by the app.
2. **Rule-based arm B (`spacedrums.prediction.rule_based`).** From the tracker's causal history (last `N = max(direction_window_frames, 2, n_min_frames)` states only — the declared `TEST-CAUSAL-2` window): CV `p̂_k = p + v kΔ` or CA `p̂_k = p + v kΔ + ½ a (kΔ)²` for `k = 1..K`, `Δ = dt_step_s`; `a` from `TrackState.tip_acceleration` (a CA filter) or a causal finite difference of the last two velocities (`ca_acceleration_source`); CA declines without an acceleration rather than degrading to CV. Heuristic `strike_probability = product | min` of a speed gate (linear ramp `speed_prob_lo → speed_prob_hi`), a direction-consistency gate (mean of `max(0, cos)` over the last `m` velocities against the current one) and a validity gate (1 for VALID, `confidence` for DEGRADED) — monotone in every gate. Declines (no prediction): empty / non-live / too short history, non-monotonic timestamps, `|v| < v_min_predict` (stopped or slow stick), `|a| > a_max` (CA). `anticipator_id = "<id>:cv|ca:K<K>:dt<Δ>"`, `model_hash = null`. Zone resolution, approach direction and the bounded horizon are the Phase 04 geometry's (`intersect_prediction`, the same routine as the reactive arm); the intensity proxy is Phase 04's crossing-speed definition for both arms (the phase document's "speed along the inward normal" variant is not introduced, so arms stay comparable).
3. **Shared commit policy (`spacedrums.commit`).** One `PerHandCommitPolicy` instance per hand **per arm**; instances share nothing. Gate order (all thresholds from the `commit` block): status (VALID; DEGRADED only when `allow_degraded_commits`) → frame-drop guard → zone validity / hand ownership → stale prediction → `strike_probability ≥ p_commit` (a candidate without a probability is not gated on it) → `t_ref − t_now ≤ tti_commit_s` → zone refractory `r_zone` → hand interval `r_hand` → episode → `n_confirm_frames` hysteresis (ARMED). Reactive commits target `t_commit`; anticipatory commits target `t_impact_pred`. `CommittedStrike.gain` comes from the Phase 04 gain curves through an injected `gain_fn` (commit and audio are peers; no import). `step` accepts a keyword-only `dropped_since_last` (current-frame information; no look-ahead) — an additive extension of the Phase 01 signature.
4. **Episode rule for anticipatory commits.** After a commit the zone machine records `commit_pending` (tip still outside) or `committed_in_episode` (tip inside). No second commit for that (hand, zone) until the tip has been observed leaving the zone, or — when the predicted crossing never materialises — until `t_impact_target + stale_prediction_tolerance_s` has passed (the same tolerance that rejects stale predictions; no extra threshold). Refractory timers (`r_zone`, `r_hand`) are the only state that survives resets other than `SESSION_START` (reset matrix); ARMED counters and episode flags are discarded on every reset and on any non-VALID frame. V1 never cancels a commit: a stop-before-impact after a commit is a false positive by definition.
5. **Shadow logging.** The active arm's instances emit `shadow = false` (scheduled to audio); every other arm's instances emit `shadow = true` (logged, `TimingRecord` written, never scheduled — the Phase 04 scheduler refuses shadow commits). A runtime switch (`a` / `b`) flips the flags and resets every instance with `ARM_SWITCH` (IDLE; timers persist).
6. **`t_now` in replay / synthetic runs.** `t_now = t_frame_available + replay_delta_proc_s` (CLI, default `0.0`, provisional), so decisions depend only on recorded stamps and a replay reproduces the committed-strike list bit-for-bit (verified by `tests/app/test_app_recorder_summary.py`). Live runs use `timing.now()`. Phase 09 defines the `Δ_proc` policy; the Phase 05 value is labelled provisional.
7. **Unmeasured audio output latency.** `AudioOutput` carries an `OutputLatency {value_s, measured, run_id}`. Without an accepted post-DAC measurement the scheduler is constructed with `0.0` **as a scheduling placeholder only**, `session.json` records `status: PENDING`, and `TimingCollector` leaves `TimingRecord.t_audio_out_est` **null** so no `L_sys_est` can be derived from a placeholder (contracts.md §3.10 rule). A measured value is accepted only together with its run id (`--audio-output-latency-s` + `--audio-latency-run-id`).
8. **Record mode / replay.** `SessionRecorder` writes `frames/*.png` (lossless) + `frames.jsonl` (raw), one header-first JSONL stream per record type + `timing.jsonl` (derived), `config.snapshot.yaml` and a Phase 05 `session.json` (developer provenance, explicitly *not* the Phase 06 `SessionMetadata`). `spacedrums.capture.ReplayFrameSource` (promoted from the Phase 03 script helper) replays a session or a Phase 02 dev capture with the original timestamps and `timestamp_source = REPLAY`.

## Consequences

- Arms A and B run under identical geometry and commit code; Phase 09/13 add arm C by registering another `Anticipator` — nothing in the decision path reads the arm.
- The candidate thresholds (`geometry.v_min 0.15`, `anticipator.rule.params.*`, `commit.*`, K = 6, dt_step = 1/30 s) are recorded in `configs/prototype.candidate.yaml` and labelled provisional; the SYNTHETIC sensitivity sweep (`scripts/rule_baseline_sensitivity.py`) shows that the tracker filter's velocity lag and `p_commit` dominate the rule arm's behaviour on synthetic strokes — a rationale for what to tune, not a tuning.
- `TEST-CAUSAL-2` for the commit policy declares a time-bounded effective window `N_eff = ceil((max(r_zone, r_hand) + stale_tolerance)/dt) + n_confirm + 1` frames, valid when no episode is open at the cut; open episodes (tip inside a zone after a commit) are an unbounded memory by design and are stated as a limitation.
- The `conftest`-import pattern of `tests/tracking` (Phase 03) is order-fragile when several test directories are given explicitly; Phase 05 keeps its helpers in uniquely named modules and documents the pre-existing fragility.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Put `v_min` into `anticipator.rule.params` | It gates the reactive arm too; a shared geometry threshold belongs to a geometry block. |
| One commit policy per hand, arms multiplexed inside | A shadow arm's decision would depend on the active arm's refractory/episode state; separate instances keep shadow logs source-agnostic. |
| Derive `t_now` from `timing.now()` in replay | Commit decisions would differ between replays (TTI/stale gates are time-dependent); the replay-determinism check would be meaningless. |
| Schedule with a guessed output latency | Forbidden by the audio profile ("no fabricated production default"); a null `t_audio_out_est` is the honest state. |
| Time-out an anticipatory episode with a new threshold | One more provisional number; the stale-prediction tolerance already expresses "how long after the target a prediction is still live". |
