# Feature schema v1 — fs-v1

Status: IMPLEMENTED; candidate engineering choices, participant validation PENDING.
Phase 08 Tasks 08.1–08.10. Contract envelope: `schemas/kinematic-features.schema.json`.
Canonical four-zone descriptor: `schemas/feature-schema-v1.json`; generated by
`FeatureSchema(load_config('configs/prototype.candidate.yaml')['zones']).descriptor()`.
The descriptor lists every ordered name, unit, group, derivation, range, scaling method and mask rule.

## Identity and dimensions

`feature_schema_id = fs-v1` identifies the algorithm family. Every export also stores the full
descriptor and its canonical SHA-256 (`feature_schema_hash`), covering zone geometry/order,
groups, epsilon and clipping. Consumers must compare that hash: the family id alone does not
identify a layout or ablation. Normalization rejects descriptor/hash mismatches. No learned
selection or test-participant optimization occurs here.

| Group | Dimension | Definition |
|---|---:|---|
| POS | 2 + 2Z | filtered ROI-normalized tip; tip minus each surface midpoint |
| VEL | 6 + Z | vx, vy, speed, unit direction x/y, explicit vertical velocity, velocity dot each inward normal |
| ACC | 5 | ax, ay, magnitude, tangential component, signed normal component |
| JERK | 3, optional, default off | jx, jy, magnitude |
| AXIS | 5 | sin(angle), cos(angle), angular velocity, axis confidence, apparent length |
| HAND | 11 | wrist/index MCP/middle MCP/thumb tip relative x/y; bbox width/height; handedness score |
| ZONE | 2Z | signed projected distance and clipped constant-velocity time-to-surface per zone |
| CONF | 5 | VALID and DEGRADED indicators, tracking confidence, frames since valid, captured drop count |
| TIME | 2 | actual dt and elapsed time within the assembled input window |

Recorded dimensions: default **F = 36 + 5Z**: 56 for MVP4, 71 for seven zones.
Full optional-jerk schema: 59 / 74 respectively. The largest proper *group* ablation of the
seven-zone full schema removes TIME (two fields), giving 72. These are schema dimensions,
not measurements of a dataset. Direction and explicit vertical velocity intentionally retain
the phase specification's redundancy; ablations may test it later.

## Causal inputs and exact derivations

`FeatureCore.update(track, hand=..., stick=..., frame=...)` accepts only the current TrackState
and optional observations with exactly matching frame id, capture time and hand identity.
Batch extraction and streaming call this same core. Future data and labels are absent from
its API. Missing observations stay masked; no hand or stick metadata is fabricated from a tip.

Coordinates retain Phase 03 ROI normalization, top-left origin and y-down convention. Position
may lie outside [0,1]; it is not silently clipped. Velocity and acceleration have units
ROI-norm/s and ROI-norm/s². Use filter velocity and acceleration whenever present. When
acceleration is null, use `(v_i-v_previous)/(t_i-t_previous)` on consecutive live TrackStates.
Optional jerk is the backward difference of these accelerations, divided by the actual dt.
The tangential component is `a dot v_hat`; signed normal is `-v_hat_y*a_x + v_hat_x*a_y`.
Speed below epsilon masks both direction and acceleration decomposition.

Axis angle uses sine/cosine and is never standardized. Angular velocity uses the filtered
value first, otherwise the wrapped backward angular difference divided by dt. Raw confidence
and length are from same-frame StickObservation; no observation means no such feature.
HAND landmarks 0,5,9,4 use `(landmark-wrist)/distance(wrist,middle_MCP)`. Zero hand size and
nonpositive supplied landmark visibility mask the affected features. Bbox size is a 2D distance
proxy, never a depth estimate. CONF's `tip_confidence` is TrackState's tracking confidence.
`dropped_since_last` comes from FrameSample, not from a guess based on skipped frame ids.

Zone geometry is read-only. Segment closest points use exact endpoint-clamped projection.
For an elliptical arc, the finite angular span is searched for local minima on a fixed
32-interval grid; each basin is minimized with bounded scalar optimization (`xatol=1e-12`),
and both endpoints are considered. This handles rotated/eccentric ellipses rather than using
a radial approximation. Tests compare distance against a dense reference (1e-8 ROI tolerance).
The distance feature is `(closest_surface_point-tip) dot inward_normal`: positive on approach,
negative beyond the surface in its inward direction. This is a **normal projection**, not an
unqualified Euclidean distance or a guarantee that the velocity ray intersects the surface.
`tts = clip(d/max(v dot n,epsilon),0,tts_clip_s)` follows the requested rule-based cue.
Receding motion saturates when above the surface; beyond-surface values clip to zero.
Candidates: epsilon 1e-6 and tts clip 2 seconds. Both are descriptor-hashed.

## Memory, masks, and gaps

Per hand, the core retains at most two previous live TrackStates and one previous processed
timestamp/id. Declared input history is **N_core=2**, or **3 when JERK is enabled**; this is
history of TrackState inputs, not a claim that the upstream filter lacks its own memory.
Warmup: two live frames for fallback acceleration/angular velocity, three for fallback jerk.
The history-truncation test compares the final record after a cold replay of that bound;
its N-1 negative control demonstrably differs. Future REMOVED/GARBAGE/SHIFTED perturbations
are bit-identical through the cut for both hands, including invalid/reacquisition frames.

INVALID and STALE: all values are zero, all masks false. Derivative history resets immediately.
Any explicit TrackState reset also clears derivative history. Reacquisition never differences
against pre-gap motion. DEGRADED features remain available with the status flags. `dt` in the
record envelope remains the interval to the previous processed frame even through an invalid
frame; the dt feature is masked on invalid frames and on the first processed frame. Nonmonotone
frame ids/timestamps and non-finite inputs are rejected. Hands have independent state.

`window_elapsed` has no meaning on a standalone per-frame record and is zero/masked there.
The *shared history assembler* sets it to `t_j-t_first_history` on live rows only. Both offline
windows and `StreamingFeatures.window()` use this assembler, preserving exact parity. It has
identity scaling. The ring retains masked rows so gaps stay visible; it never fabricates
interpolated observations. Explicit session reset clears the entire ring.

## Normalization and partitions

Per fold, use eligible, non-quarantined training **frames once**, not duplicated overlapping
windows. Fit VEL/ACC/JERK using median/IQR; other continuous features use mean/population std.
Direction, angle sine/cosine, CONF and TIME use identity scaling. Zero spread uses scale 1.
An entirely absent fitted continuous feature has count 0 and is masked on application to every
partition. Masks are applied *after* scaling; masked values remain exactly zero, never `-mean/std`.
The scheme is a candidate for Phase 09 comparison, not a participant-tuned decision.

`norm_stats.json` stores schema version, feature family/hash, names, methods, centers, scales,
counts, usable flags, fold id, dataset version/hash, split hash, source kind, training participant
ids and session ids. Loading verifies fold, dataset, split and descriptor provenance. The same
object applies to train/validation/test. Train, validation and test participants are disjoint;
their actual sessions must equal the split assignments. Missing, duplicated, unassigned and
cross-partition identities are refused. A mixed evidence-kind roster is refused. A self-test
roster can only produce a self-test dataset version.

The dataset loader verifies the existing manifest and split schemas/hashes, frozen participant
status, label-set hashes, required input file hashes, session metadata/config identity, stream
headers, raw-frame alignment, recorded QC coverage and grouping. It rechecks split leakage and
sample-level participant membership. It never creates/fixes/freeze splits as a side effect.
No participant fold can be exported while `ds-v1.0` and its reviewed labels/splits are absent.

## Window and target semantics (Tasks 08.5 and 08.7)

All N/K/H/H_max/stride/g_win are explicit run parameters. The input is the last N per-hand
frames ending at i, including masks and actual dt. Nothing after i enters X. A future change
or a label change may change T/aux, never X. Targets are ordered future **delivered frames**,
not synthesized points on a uniform clock; `target_offsets_s` stores their actual offsets.

Primary target: `T[k] = causal_tip[i+k+1]-causal_tip[i]`; `T_absolute` is stored too. Target
tracking loss/reset terminates valid target continuity: masks remain false through later
reacquisition within that target sequence. Missing tail frames and targets beyond the current
eligible segment/take are masked. **Trajectory error therefore measures prediction of the
future causal tracker output, including its noise and bias.** It does not measure physical
tip error against a manually annotated or smoothed trajectory.

Auxiliary targets use reference-derived Phase 07 labels **as targets only**: impact in `(t_i,
t_i+H]`, next-impact tti within H_max, its zone, impact position and intensity proxy. Hand,
session, segment and take must match. Rejected labels are ignored. No future impact means
tti/zone/position/intensity masks are false. Unknown recording tails cannot be confident
negatives: strike classification is masked unless the H interval is observed, or a known
positive already falls within it. AMBIGUOUS/EXCLUDED events or intervals touching the target
horizon mask auxiliary supervision and keep the sample for safety only. **Strike timing error
is against `t_impact_est`, a geometric label, not physical contact unless separately validated.**
The proposed optional reference-trajectory target experiment belongs to Phase 10 and is not
implemented. Phase 10 and Phase 18 must use these distinct interpretations.

Anticipation export requires a live anchor, no more than g_win invalid/stale history rows,
one eligible segment/take across the history, at least one valid future trajectory point, and
no ambiguous target. Every rejected complete history is retained in a separate safety file,
with all exclusion reasons. Reasons may overlap; their sum is not a count of distinct windows.
This machinery does not perform commits or claim safety of the future decision pipeline.

NPZ files use numeric X/M/T/T_absolute/T_mask/target_offsets_s, boolean anticipation eligibility,
JSON Unicode strings for aux/meta/safety reasons, and the descriptor hash; `allow_pickle=False`
works. Metadata includes frame/t_i, hand, session, participant, fold, source kind, segment/take.
Each fold writes `samples.{train,val,test}.npz` and `safety.{train,val,test}.npz`, stats and report.
Empty partitions keep the correct tensor shapes. Reports list binary strike-window counts,
masked auxiliary counts, all source label classes, dropped rates, and per-session denominators.

## Candidate sweeps (not selected model settings)

Based on Phase 02's approximately 30 FPS native developer-camera evidence, candidates are
N={8,16,32}, K={1,2,4,8}, H={0.033,0.067,0.100,0.200}s, H_max={0.3,0.5}s,
stride={1,2,4}, g_win={0,1,2}; enforce H<=H_max and g_win<=N. The Phase 08 demonstration
uses N=8,K=4,H=0.1,H_max=0.3,stride=1 (unit fold fixture stride=2),g_win=1 solely to execute
the exporter. No best setting is selected and no model is trained. Variable dt remains visible.
Group membership enables the no-ZONE/no-HAND/etc. Phase 19 ablations without data-based selection.

## Verification and evidence limits

`tests/features/`: analytic unit tests; randomized seeded gap/hand property test;
TEST-CAUSAL-1/2; normalization leakage; runtime filename/header/schema guard;
static source scan of features/models and the dataset loader; window/target alignment;
serialized SYNTHETIC session parity; full synthetic fold export. `tests/scripts/test_phase08_scripts.py`
executes the feature/statistics/latency CLIs and verifies experiment-log schemas.

The actual existing DEV CAPTURE and SYNTHETIC sessions are replayed separately. The four-group
synthetic fold fixture is an in-memory UNIT TEST fixture, with scripted targets and no recording.
It is not a participant roster. Participant fold parity, sample counts, stats and descriptive
correlations remain PENDING. See `docs/reports/phase-08-feature-stats.md` and the Phase 08 gate.

Latency measures real CPU `perf_counter_ns` intervals around streaming extraction on SYNTHETIC
records, seven-zone full/default/largest group ablation, with warmup excluded, raw timings,
hardware snapshot and p50/p95. Disk I/O, input construction and normalization are excluded.
Dirty working-tree timing is DEVELOPMENT evidence until the owner commit and clean rerun.
No model accuracy, physical latency, or reduced end-to-end latency is claimed.
